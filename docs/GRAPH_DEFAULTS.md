# 논문 그래프 기본 구성 검증

요약: Danseo skill은 짧은 제목·주제 배치·선택 중심 연결·모바일 방향 표시를 기본으로 사용한다. 세 CLI의 실제 12편 생성에서 공통 구성과 원문 검증 절차를 확인했으나 의미 정확성 전체를 인증하지는 않는다.

## 기본 동작

디자인을 따로 지시하지 않아도 포함된 생성기를 사용한다. 원래 제목과 관계 데이터는 보존한다. 주제는 편집상 해석이며 원문이 주장한 계승 관계가 아니다. 근거 상태·관계 종류를 걸러 보거나 전체 연결을 켤 수 있다. 모바일은 논문 목록 → 관계 방향 → 원문 근거로 읽는다. [입력과 화면 검수](../skills/danseo/references/research-view.md) · [원문 검증](../skills/danseo/references/relation-verification.md).

## 실제 생성 확인 — 2026-11-16

공개 RAG 관련 논문 12편의 PDF와 페이지별 추출문만 제공했다. 질문은 “RAG는 검색·융합에서 추론·검증 제어로 어떻게 발전했는가”였으며 디자인·skill 이름·검증 절차는 프롬프트에 넣지 않았다. 이전 후보나 관계 정답은 제공하지 않았다.

| 호스트 | 논문 | 주제 | 원문 관계 | AI 제안 |
| --- | ---: | ---: | ---: | ---: |
| Codex CLI | 12 | 5 | 18 | 10 |
| Claude Code | 12 | 5 | 30 | 8 |
| Antigravity CLI / Argon | 12 | 4 | 17 | 2 |

각 호스트의 최초 HTML이 같은 설치본으로 후보를 다시 렌더한 결과와 바이트 단위로 일치했다. 세 결과 모두 짧은 이름·주제를 포함하고, AI 관계는 proposed, 원문 관계는 대조 주체·시각을 보존했다. 모두 원문 읽기와 관계 작성 후 개요·수량 검사 및 verified 생성기를 사용했다. Argon은 잘못된 입력 필드가 검사에서 거부된 뒤 스스로 수정했다.

동일 OS·기존 구독 인증을 재사용한 새 설정 환경의 단일 실행이다. Codex는 별도 Linux 테스트 컨테이너, Claude·Argon은 Windows의 별도 홈·설정 폴더를 사용했다. 새 계정·모든 호스트 버전·모든 프로젝트를 검증한 결과는 아니다. 모델의 주제 분류와 관계 수까지 동일할 필요는 없다.

## 화면과 회귀 검사

세 결과를 데스크톱 1440×1000, 모바일 390×844에서 읽었다. 논문 선택·관계 방향·근거 이동과 원문/AI·관계 종류·빈 결과·전체 연결을 표본 확인했다. 긴 주제명과 첫 노드가 겹치는 문제를 수정해 두 줄 제목과 12px 간격을 확보했고, 5개 주제는 한 줄에 배치해 과도한 축소를 줄였다. 최종 화면 갱신은 원래 후보의 관계를 바꾸지 않는다.

`npm test`는 Windows Node 24에서 기존·신규 검사 86개와 원문 검사 13개를 통과했다. 최종 배치의 그래프 회귀 4개, `npm run test:package`의 설치된 skill 폴더만 복사한 HTML 생성·자산 일치·주제명 경계, `npm run check:docs`도 확인했다. PR의 CI는 별도로 확인한다. 개인 PDF·후보·원시 실행 로그·브라우저 캡처는 저장소에 배포하지 않는다.

## 의미 검증의 한계

검증 workflow 실행과 모든 문장의 타당성은 다르다. 추가 원문 대조에서 Argon이 CRAG의 성능을 모든 조건으로 일반화한 문장 하나를 발견했다. Table 1의 생성기별 예외를 반영해 파생 결과의 관계 설명·주장·조건을 교정하고 최초 생성물은 보존했다. 이 교정은 무개입 자동 성공으로 집계하지 않는다.

세 후보에는 기록·문서·쌍 수량을 인용한 검사 대상 필드가 없어 count_fields는 0이었다. 수량 오류 차단은 별도 실패 회귀에서 확인하며, 그것을 성능 비교·인용 의미 인증으로 확대하지 않는다. 원문 접근과 최종 문장 재대조, 미확인 표시가 계속 필요하다. 생성 CLI의 브라우저 부재·제한도 기록하고 최종 화면은 별도로 확인했다. 사람의 사용성·독립 이해·재현 성능은 평가하지 않았다.
