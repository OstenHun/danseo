# 기존 도구 활용 범위

요약: 문헌 관리·검색·PDF 기반 답변은 기존 도구를 활용하고, 이 프로젝트는 적용 카드·근거 관계·프로젝트별 판단·내보내기를 맡는다. 아래 연동은 문서 확인 단계이며 설치·통합 성공을 뜻하지 않는다.

확인: 2026-10-21 KST / 공식 문서와 저장소 설명. 버전 고정·라이선스 적합성·품질·운영 호환성은 실제 도입 시 확인한다.

| 기능 | 활용 후보와 현재 근거 | MVP 경계 |
| --- | --- | --- |
| 서지·PDF·주석 관리 | [Zotero](https://github.com/zotero/zotero); [공식 API 문서](https://www.zotero.org/support/dev/web_api/v3/basics)는 로컬 읽기 API도 안내한다 | 기존 관리 도구에서 파일로 내보낸 서지를 받는 한 가지 방식부터 검증. 실시간 API 동기화는 후속 |
| 로컬 의미 검색·agent 접근 | [ZotSeek](https://github.com/introfini/ZotSeek)는 로컬 검색, MCP 접근, PDF 페이지 링크를 설명한다 | 별도 기존 도구로 사용할 수 있게 원문 참조 보존. MVP 필수 의존성이나 자체 MCP 개발로 만들지 않음 |
| PDF 근거 수집·질의응답 | [PaperQA](https://github.com/Future-House/paper-qa)는 검색→근거 수집→답변과 색인 재사용을 설명한다 | 출력의 출처·조건을 검토해 카드 작성에 활용할 후속 후보. 자체 RAG/OCR을 첫 버전에 만들지 않음 |
| 프로젝트 적용 절차 | 기존 전역 paper-to-project skill(이전 이름)과 두 프로젝트의 적용 카드 | 일반 절차를 검토·재사용. 개인 설치 경로와 동결 파일럿은 배포물과 분리 |
| 시각 탐색 | 기존 GEO 프로토타입의 질문→논문→근거 흐름 | UI 원칙 재사용. 고정 데이터·개인 경로를 제거하고 같은 카드에서 뷰 생성 |

## 연결 원칙

기존 도구의 내부 소스를 복사하거나 fork하는 방식은 아직 선택하지 않았다. 먼저 파일 입출력과 외부 원문 링크를 사용한다. adapter가 실패해도 수동 카드 작성·검토·내보내기는 동작하도록 설계한다.

기존 도구에서 얻은 요약에도 원문 버전과 근거 위치가 필요하다. 검색 점수·답변 생성 성공을 사실 확인으로 바꾸지 않는다. 특정 provider나 모델 키는 core 열람·편집의 필수 조건으로 두지 않는다.

## 후속 선택 조건

검색이 실제 병목이면 ZotSeek 연결, 대량 근거 추출이 병목이면 PaperQA 검증을 연다. 기본 카드 흐름의 사용 이득이 없으면 연동 개수를 늘리는 대신 핵심 범위를 재검토한다. 공개 전에 포함한 코드·의존성·자료의 라이선스를 대조하고 프로젝트 라이선스를 선택한다.
