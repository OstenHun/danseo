# Danseo MVP

요약: 논문 근거를 프로젝트별 판단으로 재사용하는 카드·skill·로컬 웹앱을 만든다. 연구 비교와 제약이 있는 실험 조언에서 공통 형식을 검증하며, 자동 연구·클라우드 서비스는 첫 범위에서 제외한다.

상태: 초안 / 로컬 MVP 방향은 사용자 요청, 상세 요구사항은 구현 전 제안. 작성·갱신: 2026-10-21 KST. 일정·공개 릴리스 날짜·개선 목표 수치는 미정.

## 사용자와 문제

첫 사용자는 논문을 읽고 코딩 agent에게 구현·실험·연구 비교를 요청하는 CS 학습자·개발자다. 논문 사실과 프로젝트 상황을 대화마다 다시 설명하고, 근거를 잃은 요약을 재사용하거나 다른 조건의 결과를 현재 프로젝트에 잘못 옮길 수 있다.

초기 사용처는 선행연구 비교와 입출력 제약이 있는 실험 조언이다. 두 사례에서 자료와 탐색 흐름을 구성했으나 일반 사용자 수요와 지속 사용 효과는 아직 확인하지 않았다. 기존 소규모 탐색 평가는 일반 우월성·그래프 효과의 증거로 사용하지 않는다.

## 기대 결과

사용자와 agent가 같은 근거·조건을 참조하고, 어떤 논문을 왜 현재 프로젝트에 적용하거나 보류했는지 다시 찾는다. 새 질문의 근거가 부족하면 해당 원문으로 돌아가며, 카드 내용을 논문 전체의 보증으로 취급하지 않는다.

## 첫 버전의 핵심 흐름

기존 문헌 도구나 파일에서 논문 정보를 가져오기 → 출처와 확인 범위를 기록 → 프로젝트별 적용 카드 작성·저장 → 비교 표와 근거 패널로 검토 → 관계 그래프로 탐색 → 선택 항목을 Markdown 근거 묶음으로 내보내 agent에 전달.

## 포함할 결과

| ID | 사용자 상황과 요구사항 | 수용 신호 |
| --- | --- | --- |
| M1 | 같은 논문을 다른 프로젝트에서 사용한다. 논문·주장·근거와 프로젝트 적용 판단을 연결한다 | 연구 비교·실험 조언 각각의 카드가 공통 형식으로 표현되고 프로젝트를 바꿔도 원문 사실이 중복 변경되지 않는다 |
| M2 | 카드의 근거와 상태를 검토한다. 원문 판본·locator·확인 범위, AI 해석·프로젝트 관찰·판단 상태를 구분한다 | 필수 근거 누락·끊어진 참조를 알리고, URL 존재를 내용의 참으로 판정하지 않는다 |
| M3 | 로컬 웹앱에서 카드를 만들고 고쳐 보관한다 | 저장 뒤 앱을 닫았다 열어도 변경이 유지되고, 불러오기 오류는 원본을 덮어쓰지 않는다 |
| M4 | 프로젝트별 관련 논문을 비교하고 관계를 따라간다 | 비교 표·근거 패널·기본 그래프가 동일 기록을 반영하며 인용과 분석자 연결을 구분한다 |
| M5 | 기존 agent에 작업을 맡긴다 | 선택 카드·프로젝트 조건·원문 위치·미확인 사항을 묶어 내보내고, 공통 skill이 이를 읽어 원문 확인과 적용 판단을 수행한다 |
| M6 | 기존 도구의 자료를 활용한다 | 첫 입력은 명시적인 파일 가져오기이며 native workspace round-trip을 보장한다. 기존 도구의 한 가지 서지 export 형식은 PTP-001 후 선택·검증한다 |

공통 skill은 기존 agent에서 실행한다. 웹앱 내 자체 agent 실행·유료 API 호출은 필수가 아니다. 수동 작성으로도 핵심 흐름을 사용할 수 있어야 한다.

## 이번에 제외

자체 논문 검색 엔진, 자체 PDF/OCR 파서, 자동 신규성 판정, 자동 실험·사이트 제출, 계정·결제·멀티유저 동기화, 클라우드 저장, 전 분야 온톨로지, 복잡한 그래프 DB, MCP 서버 자체 구현. Zotero 실시간 연결과 PaperQA 실행 연결은 core 검증 뒤 별도 후속이다.

## 두 사용처의 차이

연구 비교에서는 질문·비교군·평가 조건·차별화 후보를 검토한다. 실험 조언에서는 과제·모델·입출력 제약·기존 성공/실패를 대조한다. 논문 결과는 공통이며 연구 신규성이나 외부 평가 결과의 근거는 각 프로젝트 정본이 소유한다. 서로 다른 프로젝트에 같은 실험 지표를 억지로 요구하지 않는다.

## 성공 확인과 한계

동작 완료는 M1–M6의 실제 저장·조회·내보내기·검사로 확인한다. 사용 가치 판단은 [평가 계획](../evals/README.md)의 근거 도달, 잘못된 전이, 조건 누락, 소요 시간, 유지 비용으로 별도 확인한다. 기준값·개선 목표는 새 사전 평가에서 고정하며 지금 숫자를 약속하지 않는다.

카드와 skill의 조언 품질, 그래프의 사람 탐색 효과를 따로 본다. agent가 그래프 그림을 보지 않았다면 agent 개선을 그래프 효과로 해석하지 않는다. 원문 전체를 생략하는 것 자체를 성공 지표로 삼지 않는다.
